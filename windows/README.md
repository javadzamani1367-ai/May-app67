# آرشیو مرکزی — نرم‌افزار ویندوز (فاز ۶)

دریافت‌کننده و آرشیو مرکزی پرونده‌های بازدید. پرونده‌ها را از گوشی کارشناس
می‌گیرد، در یک پایگاه داده رمزنگاری‌شده نگه می‌دارد و خروجی تجمیعی می‌سازد.

## نیازمندی‌ها

| مورد | نسخه |
|---|---|
| سیستم‌عامل | ویندوز ۷ SP1 (۶۴ بیتی) یا بالاتر |
| .NET Framework | ۴.۸ |
| Visual C++ Redistributable | ۲۰۱۵–۲۰۲۲ (برای SkiaSharp که موتور PDF از آن استفاده می‌کند) |
| برای ساخت | Visual Studio 2019 یا msbuild با ابزارهای ۴.۸ |

> ویندوز ۷ باید SP1 و به‌روزرسانی‌های امنیتی SHA-2 را داشته باشد، وگرنه
> .NET Framework 4.8 نصب نمی‌شود.

## ساخت

```cmd
nuget restore CryptoInspection.sln
msbuild CryptoInspection.sln /p:Configuration=Release /p:Platform="Any CPU"
```

خروجی در `CryptoInspection.Archive\bin\Release\` قرار می‌گیرد.

### فونت وزیرمتن

مثل سمت اندروید، فایل فونت در مخزن نگهداری نمی‌شود. این دو فایل را از
[github.com/rastikerdar/vazirmatn](https://github.com/rastikerdar/vazirmatn)
(مجوز SIL OFL) در این مسیر بگذارید:

```
CryptoInspection.Archive\Assets\fonts\Vazirmatn-Regular.ttf
CryptoInspection.Archive\Assets\fonts\Vazirmatn-Bold.ttf
```

بدون آن، برنامه با فونت Tahoma کار می‌کند و خروجی PDF هم با همان ساخته می‌شود.

## بسته‌های استفاده‌شده

| بسته | نقش | مجوز |
|---|---|---|
| `Microsoft.Data.Sqlite.Core` + `SQLitePCLRaw.bundle_e_sqlcipher` | SQLite با رمزنگاری SQLCipher | MIT / Apache-2.0 |
| `QuestPDF` ۲۰۲۳.۱۲ | تولید PDF راست‌به‌چپ | MIT |
| `SkiaSharp.NativeAssets.Win32` | موتور ترسیم مورد نیاز QuestPDF | MIT |
| `DocumentFormat.OpenXml` | تولید Word | MIT |
| `ClosedXML` | تولید اکسل | MIT |
| `Portable.BouncyCastle` | رمزگشایی AES-GCM بسته `.cvz` | MIT |

نسخه QuestPDF عمداً روی ۲۰۲۳.۱۲ ثابت شده است؛ نسخه‌های ۲۰۲۴ به بعد مجوز
دوگانه دارند. تجزیه JSON با `JavaScriptSerializer` خود فریم‌ورک انجام می‌شود
تا وابستگی تازه‌ای اضافه نشود.

**درباره حجم:** هدف «زیر ۱۵ مگابایت» در مستند اصلی با QuestPDF سخت به دست
می‌آید، چون کتابخانه بومی Skia به تنهایی حدود ۸ مگابایت است. خروجی Release
تک‌معماری (x64) حدود ۱۶ تا ۱۸ مگابایت و پس از فشرده‌سازی نصاب حدود ۱۰ تا ۱۲
مگابایت می‌شود. اگر حجم قطعی و غیرقابل‌مذاکره است، جایگزین بدون Skia برای
تولید PDF لازم است.

## کارکردها

- **بایگانی:** جستجوی همه پرونده‌ها روی کد رهگیری، آدرس، شماره اشتراک و نام مالک
- **دریافت از گوشی:** اتصال وای‌فای یا `adb forward` با کد شش‌رقمی، دریافت
  افزایشی بر اساس `updated_at`، ذخیره رسانه‌ها و سپس `POST /ack`
- **دریافت بسته آفلاین:** وارد کردن فایل `.cvz` با رمزی که روی گوشی نمایش داده می‌شود
- **گزارش‌گیری:** خروجی اکسل با فیلتر تاریخ شمسی، شهرستان و وضعیت (به‌همراه شیت
  آمار تجمیعی) و بازسازی فرم PDF یا Word برای پرونده انتخاب‌شده

## نکته‌های پیاده‌سازی

- اسکیما دقیقاً همان چیزی است که Room روی گوشی می‌سازد؛ مرجع: `SCHEMA.md`.
  `Schema.Version` باید با `SCHEMA_VERSION` اندروید یکی باشد وگرنه ادغام انجام نمی‌شود.
- ادغام روی `id` (UUID) انجام می‌شود و idempotent است: پرونده تکراری به‌روزرسانی
  می‌شود، نه رکورد تازه. فرزندان (دستگاه‌ها، حاضرین، رسانه، پیوست، ارسال‌ها)
  یکجا جایگزین می‌شوند چون گوشی مرجع است.
- تا وقتی همه فایل‌های یک پرونده ذخیره نشده‌اند `ack` فرستاده نمی‌شود؛ قطع کابل
  وسط کار یعنی تکرار، نه از دست رفتن داده.
- رمز پایگاه داده با DPAPI برای کاربر جاری ویندوز محافظت می‌شود و کنار فایل
  پایگاه داده به صورت متن ساده ذخیره نمی‌شود.
- مسیر فایل‌ها در پایگاه داده نسبی می‌ماند، پس پوشه آرشیو قابل جابه‌جایی است.
