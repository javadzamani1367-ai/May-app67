# سرور سامانه بازدید مراکز رمزارز

بک‌اند روی **هاست اشتراکی با PHP و MySQL** (سی‌پنل). بدون فریم‌ورک، بدون
composer و بدون هیچ پروسه دائمی — چون روی هاست اشتراکی معمولاً نه دسترسی خط
فرمان هست و نه اجازه نصب بسته. یک پوشه کپی می‌شود و کار می‌کند.

---

## ۱. چه چیزی نیاز دارید

| مورد | حداقل |
|---|---|
| PHP | ۸٫۰ به بالا |
| افزونه‌ها | `pdo_mysql` و `mbstring` (روی تقریباً همه هاست‌ها فعال است) |
| MySQL / MariaDB | هر نسخه‌ای که سی‌پنل می‌دهد |
| فضا | برای شروع ۱ گیگابایت؛ تصاویر پرونده‌ها با زمان زیاد می‌شوند |
| SSL | گواهی رایگان Let's Encrypt سی‌پنل کافی است — **حتماً روشن باشد** |

---

## ۲. نصب، قدم به قدم

### قدم ۱ — پایگاه داده بسازید
در سی‌پنل → **MySQL Databases**:
1. یک پایگاه داده بسازید، مثلاً `inspection`
2. یک کاربر بسازید و رمز قوی بگذارید
3. کاربر را با دسترسی **ALL PRIVILEGES** به آن پایگاه داده اضافه کنید
4. نام کامل پایگاه داده و کاربر را یادداشت کنید (سی‌پنل جلوی هر دو، نام حساب شما را می‌گذارد، مثل `myaccount_inspection`)

### قدم ۲ — جدول‌ها را وارد کنید
سی‌پنل → **phpMyAdmin** → پایگاه داده را انتخاب کنید → زبانه **Import** →
فایل `schema.sql` را بدهید → Go.
باید ۱۴ جدول ساخته شود.

### قدم ۳ — فایل‌ها را بالا ببرید
پوشه `api` را داخل `public_html` کپی کنید، یعنی:

```
public_html/
└── api/
    ├── index.php
    ├── .htaccess
    ├── config.php        ← این را در قدم بعد می‌سازید
    ├── lib/
    ├── portal/
    └── storage/
```

### قدم ۴ — فایل تنظیمات را بسازید
`api/config.sample.php` را به `api/config.php` کپی کنید و پر کنید:

```php
'db_name' => 'myaccount_inspection',
'db_user' => 'myaccount_inspection',
'db_pass' => 'رمزی که در قدم ۱ گذاشتید',
'app_key' => 'یک رشته تصادفی ۶۴ نویسه‌ای',
```

`app_key` را یک بار بگذارید و **دیگر عوضش نکنید**: با آن توکن‌های ورود
ساخته می‌شوند و تغییرش همه کاربران را از حساب بیرون می‌اندازد.

### قدم ۵ — دسترسی پوشه ذخیره‌سازی
در File Manager روی پوشه `api/storage` راست‌کلیک → Change Permissions →
`755` (اگر نشد `775`). این پوشه باید قابل نوشتن باشد.

### قدم ۶ — بررسی نصب
آدرس زیر را باز کنید:

```
https://دامنه-شما/api/install-check.php
```

تا وقتی همه ردیف‌ها «آماده» نشده‌اند جلو نروید. بعد از سبز شدن، **این فایل
را حذف کنید**.

### قدم ۷ — حساب مدیر و واحدها
یک بار این آدرس را باز کنید:

```
https://دامنه-شما/api/setup.php
```

نام، کد کاربری و رمز مدیر را بدهید. این صفحه حساب مدیر و حساب چهار واحد
مقصد را می‌سازد و **رمز واحدها را یک بار نشان می‌دهد** — همان‌جا یادداشت
کنید. بعد از آن `setup.php` را حذف کنید. (این صفحه به‌محض وجود اولین کاربر
خودش را می‌بندد، ولی ماندنش روی هاست لازم نیست.)

### قدم ۸ — آدرس سرور را در اپ وارد کنید
در اپ اندروید → تنظیمات → «آدرس مقصد همگام‌سازی»:

```
https://دامنه-شما/api
```

---

## ۳. پرتال واحدهای مقصد

واحد فروش، حراست، حقوقی و برق شهرستان **هیچ برنامه‌ای نصب نمی‌کنند**. با
مرورگر وارد می‌شوند:

```
https://دامنه-شما/api/portal/login.php
```

آنجا مدارک ارسال‌شده را می‌بینند، فایل‌ها را دانلود می‌کنند، و نتیجه اقدام
را با متن و مستندات (تصویر، PDF، ورد) ثبت می‌کنند. با ثبت پاسخ، برای مدیر
اعلان ساخته می‌شود.

---

## ۴. اعلان‌ها روی هاست اشتراکی

هاست اشتراکی پروسه دائمی و وب‌سوکت ندارد، پس اعلان «فرستاده» نمی‌شود:
در جدول `notifications` می‌نشیند و اپ و نرم‌افزار ویندوز با هر بار
همگام‌سازی آن را می‌خوانند و خودشان نمایش می‌دهند. ساده است، روی هر هاستی
کار می‌کند، و هیچ سرویس جانبی نمی‌خواهد.

---

## ۵. نقاط انتهایی

همه پاسخ‌ها JSON با شکل ثابت `{"ok":true,"data":{…}}` یا
`{"ok":false,"error":{"code":"…","message":"…"}}` هستند.
احراز هویت با سربرگ `Authorization: Bearer <token>`.

| مسیر | شرح |
|---|---|
| `GET /ping` | سلامت سرویس و نسخه اسکیما |
| `POST /auth/login` | ورود با کد کاربری، رمز و کد دستگاه |
| `POST /auth/request-device` | ثبت درخواست دستگاه جدید (در صف مدیر) |
| `GET /users` · `POST /users/save` | مدیریت کاربران — فقط مدیر |
| `GET /sync/manifest?since=` | شناسه پرونده‌های تغییرکرده |
| `POST /sync/report` · `GET /sync/report?id=` | ارسال و دریافت یک پرونده |
| `POST /sync/file` · `GET /sync/file?path=` | بارگذاری و دریافت فایل |
| `POST /approvals/submit` · `POST /approvals/decide` | گردش تأیید مدیر |
| `POST /dispatches/create` · `GET /dispatches?report_id=` | ارسال مدارک و سوابق آن |
| `GET /dispatches/inbox` · `POST /dispatches/respond` | صندوق و پاسخ واحد |
| `GET /notifications?since=` | اعلان‌های تازه |
| `GET /stats/units` | گزارش عملکرد واحدها |

اگر `mod_rewrite` روی هاست خاموش بود، همین مسیرها به شکل
`index.php?route=auth/login` هم کار می‌کنند — کلاینت خودش این را مدیریت می‌کند.

---

## ۶. نکات امنیتی که رعایت شده

- رمزها با `password_hash` ذخیره می‌شوند، نه رمزگذاری برگشت‌پذیر
- توکن نشست **خام ذخیره نمی‌شود**؛ فقط SHA-256 آن در جدول می‌نشیند
- ورود ناموفق برای «کاربر نیست» و «رمز غلط» پیام یکسان می‌دهد، تا فهرست کدهای کاربری معتبر از تفاوت پیام بیرون نیاید
- حساب کارشناس به کد دستگاه ثبت‌شده بسته است؛ ورود از نصب دیگر رد می‌شود
- فایل‌های پرونده در `storage` هستند و با `.htaccess` از وب مسدودند؛ فقط از مسیر دانلود و بعد از بررسی نشست بیرون می‌روند
- `config.php` هم از وب مسدود است و در مخزن گیت قرار نمی‌گیرد
- همه کوئری‌ها پارامتری هستند (`PDO` با `EMULATE_PREPARES = false`)
- متن خطای داخلی هرگز به کلاینت نمی‌رود؛ در لاگ هاست می‌ماند

## ۷. قفل دستگاه — بدون پیامک

حساب هر کارشناس به **کدی که خود گوشی می‌سازد** بسته است. پیامک و سرویس
پیامکی در کار نیست.

۱. کارشناس برنامه را نصب می‌کند. برنامه در همان اولین اجرا یک کد ۶۴ بیتی
   تصادفی برای خودش می‌سازد و در صفحه ورود نشان می‌دهد.
۲. کارشناس دکمه «ارسال درخواست ثبت این دستگاه» را می‌زند؛ کد دستگاه همراه
   نام و شماره همراهش به سرور می‌رود و در صف مدیر می‌نشیند. (اگر اینترنت
   نداشت، کد را به مدیر می‌گوید.)
۳. مدیر در «مدیریت کاربران سامانه» همان کد را با نام، شهرستان، کد کاربری و
   شماره همراه ثبت می‌کند و رمز عبور می‌دهد.
۴. از این پس ورود آن کد کاربری **فقط از همان نصب** ممکن است. سرور در
   `Auth::login()` کد دستگاه را با کد ثبت‌شده مقایسه می‌کند و ورود از نصب
   دیگر را با پیام «این حساب روی دستگاه دیگری ثبت شده است» رد می‌کند.
۵. با حذف برنامه یا تعویض گوشی، کد از بین می‌رود و ساخته‌شدن دوباره‌اش
   تصادفی است. یعنی کارشناس باید دوباره درخواست بدهد و مدیر کد تازه را ثبت
   کند — همان رفتاری که خواسته شده بود.

**اولین ورود باید آنلاین باشد**، چون تطبیق روی سرور انجام می‌شود. بعد از آن
گوشی به‌تنهایی باز می‌شود و کار میدانی بدون اینترنت ادامه دارد. هر وقت
سرور در دسترس باشد دوباره پرسیده می‌شود، و اگر مدیر حساب را غیرفعال یا به
گوشی دیگری منتقل کرده باشد، فعال‌سازی همان‌جا برداشته می‌شود و ورود بعدی
باید دوباره آنلاین باشد.

شماره همراه ثبت می‌شود تا در سوابق بماند، ولی چیزی که ورود را قفل می‌کند
کد دستگاه است، نه شماره.
