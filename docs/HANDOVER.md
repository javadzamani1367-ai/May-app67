و باید بتواند بدون پرسیدن از کسی، کد را بفهمد و تغییر بدهد.

## ۱. سامانه در یک صفحه

شرکت توزیع برق استان ایلام از مراکز استخراج رمزارز بازدید می‌کند. هر بازدید یک
**پرونده** است که از لحظه رسیدن گزارش تا ارسال مدارک به واحدهای سازمانی، یک چرخه
کامل را طی می‌کند:

```
گزارش می‌رسد ──▶ ثبت سریع (کد رهگیری ساخته می‌شود)
                        │
                        ▼
                 صف «در دست اقدام»
                        │
                        ▼
              بازدید میدانی، پنج مرحله
       (مکان و GPS ← مالک ← فنی ← دستگاه‌ها و حاضرین ← تصاویر و شرح)
                        │
                        ▼
            کارشناس برای تأیید می‌فرستد ──▶ مدیر تأیید می‌کند
                        │                       یا برای اصلاح برمی‌گرداند ─┐
                        ▼                                                  │
                 «بازدید شده»  ◀──────────────────────────────────────────┘
                        │
                        ▼
        تولید فرم رسمی (PDF / Word) + پیوست مدارک
                        │
                        ▼
      ارسال گزینشی به واحد (فروش / حراست / حقوقی / برق شهرستان)
        با مهلت پاسخ، و ثبت در سابقه ارسال همان پرونده
                        │
                        ▼
                    بایگانی
```

### سه نرم‌افزار

| نرم‌افزار | کجا اجرا می‌شود | نقش |
|---|---|---|
| اپ اندروید — نسخه **کارشناس** | گوشی کارشناس میدانی | ابزار اصلی کار؛ همه چیز آفلاین |
| اپ اندروید — نسخه **مدیر** | گوشی مدیر | همان کد، با صف تأیید، مدیریت کاربران و گزارش عملکرد |
| نرم‌افزار **ویندوز** | کامپیوتر دفتر (ویندوز ۷ به بالا) | آرشیو مرکزی و گزارش‌گیری تجمیعی |
| **سرور** PHP/MySQL | هاست اشتراکی سی‌پنل | ورود کاربران، تأییدها، اعلان‌ها، پرتال واحدها |

دو اپ اندروید **از یک کدبیس** ساخته می‌شوند: دو product flavor به نام `expert` و
`manager`. هیچ کد تکراری وجود ندارد.

## ۲. پنج قاعده‌ای که نباید شکسته شود

اگر فقط یک بخش از این سند را می‌خوانید، همین باشد. هر کدام از این‌ها به یک
محدودیت واقعی وصل است، نه به سلیقه:

1. **آفلاین‌اول.** کارشناس در منطقه‌ای کار می‌کند که آنتن ندارد. هیچ قابلیت
   میدانی نباید به شبکه نیاز داشته باشد. سرور روی این معماری *اضافه* شده، جایش
   را نگرفته.
2. **اسکیما در سه جا یکی است.** هر تغییر ستون باید در اندروید، ویندوز و سرور
   اعمال شود. `php server/tests/run.php` این را بررسی می‌کند و اگر یکی جا بماند
   تست شکست می‌خورد. → [بخش ۷](#۷-تغییر-اسکیما-چهار-جا)
3. **هیچ رشته فارسی داخل کد نیست.** همه در `strings.xml` (اندروید) و
   `Resources/Strings.xaml` (ویندوز). فقط کامنت و مستند فارسی است.
4. **تاریخ در پایگاه داده همیشه یونیکس میلی‌ثانیه است.** تبدیل به شمسی فقط در
   لایه نمایش. هیچ‌جا رشته تاریخ شمسی ذخیره نمی‌شود.
5. **هر فایل حداکثر ۳۰۰ خط.** `python3 tools/verify-resources.py` این را هم
   بررسی می‌کند. فایل بزرگ‌تر یعنی آن فایل دو کار می‌کند و باید شکسته شود.

به‌علاوه سه قاعده امنیتی که در [`DECISIONS.md`](DECISIONS.md) توضیح داده شده:
پایگاه داده با SQLCipher رمزنگاری می‌شود، کلید امضای اپ هرگز داخل مخزن نمی‌آید،
و فایل `server/api/config.php` (رمز پایگاه داده) در `.gitignore` است.

## ۴. معماری اپ اندروید

### لایه‌ها

```
 ui/            ← Compose. فقط نمایش و رویداد. هیچ منطقی اینجا نیست.
   ↓ (ViewModel در همان پوشه صفحه)
 data/repo/     ← منطق کار: قواعد پرونده، ساخت کد رهگیری، ذخیره فایل
   ↓
 data/db/       ← Room: موجودیت‌ها و DAOها. فقط SQL.
```

و کنارشان:

```
 data/model/    ← enumها، مدل دامنه، قواعدی که به اندروید وابسته نیستند (تست‌پذیر)
 export/        ← تولید PDF، Word، Excel
 sync/          ← وب‌سرور روی گوشی، کلاینت سرور، بسته آفلاین
 util/          ← تاریخ شمسی، ارقام، توان، مهر تصویر، رمزنگاری، موقعیت
```

**قاعده‌ای که همه‌جا رعایت شده:** منطقی که باید تست شود در `data/model/` یا
`util/` است، چون آن دو پوشه به `Context` اندروید وابسته نیستند و با
`./gradlew test` روی JVM اجرا می‌شوند. اگر منطق جدیدی می‌نویسید که ارزش تست دارد،
همان‌جا بگذاریدش، نه در ViewModel.

### چطور یک صفحه وصل می‌شود

هر صفحه همین سه تکه است — یک نمونه از `StatsScreen.kt`:

```kotlin
val appContainer = LocalContext.current.container          // ۱. ظرف وابستگی‌ها
val viewModel: StatsViewModel = viewModel(                 // ۲. ViewModel از همان ظرف
    factory = remember { ContainerViewModelFactory(appContainer) { StatsViewModel(it) } }
)
val total by viewModel.total.collectAsStateWithLifecycle() // ۳. StateFlow → state
```

هیچ کتابخانه تزریق وابستگی‌ای (Hilt، Koin) استفاده نشده. `AppContainer` یک کلاس
ساده با فیلدهای `by lazy` است — دلیلش در [`DECISIONS.md`](DECISIONS.md).

### دو نسخه اپ از یک کد

در `android/app/build.gradle.kts`:

```kotlin
flavorDimensions += "role"
productFlavors {
    create("expert") {
        applicationIdSuffix = ".expert"
        buildConfigField("boolean", "MANAGER", "false")
    }
    create("manager") {
        applicationIdSuffix = ".manager"
        buildConfigField("boolean", "MANAGER", "true")
    }
}
```

و در کد **همیشه** از این یکی خوانده می‌شود:

```kotlin
if (UserRole.isManager) { /* صف تأیید، مدیریت کاربران، گزارش عملکرد */ }
```

نقش از یک تنظیم خوانده **نمی‌شود**، چون یک تنظیم را کارشناس می‌تواند عوض کند و
خودش را مدیر کند. دو `applicationIdSuffix` متفاوت یعنی هر دو نسخه می‌توانند
هم‌زمان روی یک گوشی نصب باشند.

## ۵. معماری سرور

```
server/
├── schema.sql          ← ۱۴ جدول. یک‌بار در phpMyAdmin وارد می‌شود.
├── README.md           ← نصب قدم‌به‌قدم روی سی‌پنل
├── tests/run.php       ← تست‌ها، بدون PHPUnit، روی خود هاست هم اجرا می‌شود
└── api/
    ├── index.php       ← تنها ورودی. جدول مسیرها همین‌جاست.
    ├── .htaccess       ← بازنویسی مسیر، با جایگزین index.php?route=…
    ├── config.php      ← رمز پایگاه داده. در .gitignore. هرگز در مخزن نیست.
    ├── install-check.php  ← بعد از نصب یک‌بار باز می‌شود و همه چیز را می‌سنجد
    ├── setup.php       ← ساخت اولین مدیر
    ├── lib/
    │   ├── Db.php, Config.php, Request.php, Response.php
    │   ├── Auth.php        ← توکن، نقش، و مهار دستگاه
    │   ├── Storage.php     ← فایل پرونده‌ها، بیرون از public
    │   ├── Notifications.php
    │   ├── Jalali.php      ← همان الگوریتم اپ، عیناً
    │   └── Controllers/    ← یکی به ازای هر خانواده مسیر
    └── portal/             ← صفحات واحدها (فروش، حراست، حقوقی، برق شهرستان)
```

**بدون فریم‌ورک و بدون composer**، چون روی هاست اشتراکی نه خط فرمان هست و نه
اجازه نصب بسته. یک پوشه کپی می‌شود و کار می‌کند.

افزودن مسیر جدید = یک سطر در `$routes` داخل `index.php` و یک متد در یک کنترلر.
هیچ فایل تنظیمات دیگری وجود ندارد.

قواعد امنیتی سرور که در هر تغییری باید حفظ شوند:

- هر پرس‌وجو پارامتری است؛ `PDO::ATTR_EMULATE_PREPARES = false`
- توکن ورود فقط به‌صورت SHA-256 از توکن + `app_key` ذخیره می‌شود
- «کاربر وجود ندارد» و «رمز غلط» یک پیام یکسان می‌گیرند
- متن خطای داخلی هرگز به کلاینت نمی‌رود؛ در لاگ هاست می‌ماند
- فایل پرونده‌ها بیرون از ریشه وب است و فقط بعد از بررسی نشست سرو می‌شود

## ۶. معماری نرم‌افزار ویندوز

.NET Framework 4.8 و WPF، چون باید روی **ویندوز ۷ SP1** نصب شود. همین یک
محدودیت، Electron جدید و Tauri و Flutter Desktop را حذف می‌کند.

```
windows/CryptoInspection.Archive/
├── Data/        ← SQLite + SQLCipher، همان اسکیمای اندروید
├── Sync/        ← دریافت از گوشی (HTTP) و وارد کردن بسته .cvz
├── Export/      ← PDF (QuestPDF)، Word (OpenXml)، Excel (ClosedXML)
├── ViewModels/  ← MVVM دستی، بدون کتابخانه
├── Views/       ← XAML، راست‌به‌چپ
├── Util/        ← PersianDate (همان الگوریتم)، ارقام، فونت، برچسب‌ها
└── Resources/   ← Strings.xaml و Theme.xaml
```

نکته‌ای که موقع تغییر باید بدانید: `Util/PersianDate.cs` و
`android/.../util/PersianDate.kt` و `server/api/lib/Jalali.php` **یک الگوریتم**
هستند و باید یکی بمانند. اگر یکی را تغییر دادید، هر سه را تغییر بدهید و
`php server/tests/run.php` را اجرا کنید.

## ۷. تغییر اسکیما — چهار جا

این پرخطرترین تغییر در کل پروژه است. یک ستون جدید باید در **چهار جا** اضافه شود:

| # | جا | کار |
|---|---|---|
| ۱ | `android/.../data/db/ReportEntity.kt` | فیلد + `@ColumnInfo(name = "…")` |
| ۲ | `android/.../data/db/AppDatabase.kt` | `DATABASE_VERSION` را یکی جلو ببرید و یک `Migration` تازه با `ALTER TABLE … ADD COLUMN` بنویسید — **هرگز جدول را نسازید و دوباره نسازید**: گوشی کارشناس تا قبل از همگام‌سازی تنها نسخه پرونده را دارد |
| ۳ | `server/schema.sql` + `SyncController::REPORT_COLUMNS` | ستون در جدول، و نامش در فهرست ستون‌هایی که واقعاً منتقل می‌شوند |
| ۴ | `windows/CryptoInspection.Archive/Data/Schema.cs` + `windows/SCHEMA.md` | DDL و مستند |

اگر ستون جدید باید بین گوشی و ویندوز و سرور جابه‌جا شود، `SCHEMA_VERSION` هم یکی
جلو می‌رود — و آن عدد در **سه زبان** نوشته شده:

```
android/.../data/db/AppDatabase.kt                → const val SCHEMA_VERSION
server/api/lib/Controllers/SystemController.php   → public const SCHEMA_VERSION
windows/.../Data/Schema.cs                        → public const int Version
windows/SCHEMA.md                                 → عدد مستندشده
```

هیچ کامپایلری این چهار را با هم مقایسه نمی‌کند، پس تست این کار را می‌کند:

```bash
php server/tests/run.php
```

اگر یکی جا بماند، تست شکست می‌خورد و می‌گوید کدام. (همین تست، دفعه اول که نوشته
شد، سه ستون تأیید مدیر را پیدا کرد که در گوشی و ویندوز بودند و در سرور نبودند —
یعنی وضعیت تأیید پرونده به سرور می‌رفت و بی‌صدا دور ریخته می‌شد.)

اگر ستون جدید فقط روی گوشی معنا دارد (مثل جدول `snippets`)، فقط
`DATABASE_VERSION` جلو می‌رود و `SCHEMA_VERSION` دست نمی‌خورد. دلیل جدا بودن این
دو عدد همین است.

## ۸. ساخت، اجرا، تست

### اپ اندروید

```bash
cd android
./gradlew assembleExpertDebug      # اپ کارشناس
./gradlew assembleManagerDebug     # اپ مدیر
./gradlew test                     # تست‌های واحد روی JVM
```

نیازمندی: JDK 17، Android SDK با API 34.

فونت وزیرمتن به دلیل مجوز و حجم داخل مخزن نیست. بدون آن هم ساخته می‌شود (فونت
سیستم)، ولی برای نسخه نهایی این دو فایل را از
[rastikerdar/vazirmatn](https://github.com/rastikerdar/vazirmatn) بگیرید:

```
android/app/src/main/assets/fonts/Vazirmatn-Regular.ttf
android/app/src/main/assets/fonts/Vazirmatn-Bold.ttf
```

### سرور

```bash
php server/tests/run.php           # ۴۷ تست، بدون نیاز به پایگاه داده
```

نصب روی هاست: [`../server/README.md`](../server/README.md). بعد از نصب یک‌بار
`install-check.php` را در مرورگر باز کنید — هر چیزی که غلط باشد را نام می‌برد.

### نرم‌افزار ویندوز

```cmd
cd windows
nuget restore CryptoInspection.sln
msbuild CryptoInspection.sln /p:Configuration=Release
```

### بررسی‌های سریع — قبل از هر commit

```bash
python3 tools/verify-resources.py  # منابع تکراری، ارجاع به منبع نبوده، قاعده ۳۰۰ خط
php server/tests/run.php           # تاریخ شمسی، نحو PHP، یکسانی اسکیما
cd android && ./gradlew test
```

دو مورد اول در یک ثانیه جواب می‌دهند و هر دو دقیقاً به خاطر خطاهایی نوشته شدند
که یک‌بار اتفاق افتاده بودند. هر سه، اولین قدم‌های CI هم هستند.

### CI

`.github/workflows/android.yml` روی هر push به شاخه توسعه اجرا می‌شود و:

۱. بررسی‌های سریع بالا را انجام می‌دهد (قبل از هر کامپایلی)
۲. APK نسخه debug را می‌سازد و به همان اجرا پیوست می‌کند
۳. نسخه release را می‌سازد و امضا می‌کند
۴. اگر تگ `v*` زده باشید، آن را به‌صورت Release منتشر می‌کند

کلید امضا در GitHub Secrets است، نه در مخزن. طریقه ساختش در
[`../README.md`](../README.md).

## ۹. وضعیت کار — چه تمام است و چه نیست

### تمام‌شده و کارکرده

| بخش | وضعیت |
|---|---|
| پایه: تم راست‌به‌چپ، Room + SQLCipher، تاریخ شمسی، تنظیمات | ✅ |
| چرخه اصلی: ثبت سریع، کد رهگیری، صف، بازدید پنج‌مرحله‌ای، GPS، دوربین، بارکد | ✅ |
| خروجی: PDF، Word، Excel، اشتراک‌گذاری | ✅ |
| مدارک: پیوست پس از بازدید، ارسال گزینشی، سابقه ارسال، مهلت پاسخ | ✅ |
| چرخه تأیید مدیر، برگشت برای اصلاح، صف تأیید | ✅ |
| ورود با کد کارشناس، مهار دستگاه، مدیریت کاربران توسط مدیر | ✅ |
| گزارش عملکرد واحدها در سه قالب | ✅ |
| همگام‌سازی با ویندوز: وب‌سرور گوشی، USB، بسته `.cvz` | ✅ |
| نرم‌افزار ویندوز: دریافت، آرشیو، گزارش‌گیری | ✅ |
| سرور: مسیرها، احراز هویت، اعلان‌ها، پرتال واحدها | ✅ نوشته‌شده |

### آنچه باید بدانید تمام نیست

این‌ها صادقانه نوشته شده‌اند تا وقتتان سر کشف دوباره‌شان هدر نرود:

1. **پرونده‌ها به سرور فرستاده نمی‌شوند.** امروز ورود، ثبت دستگاه، مدیریت
   کاربران، تأییدها و آمار واحدها با سرور حرف می‌زنند. اما انتقال خود پرونده
   همچنان مسیر وای‌فای / USB / `.cvz` به ویندوز است. نقاط انتهایی سرور برای این
   کار (`POST /sync/report`، `POST /sync/file`) نوشته و آماده‌اند؛ چیزی که نیست،
   کد سمت گوشی است که آن‌ها را صدا بزند. طبیعی‌ترین جا برای افزودنش:
   `sync/ServerApi.kt` کنار متدهای موجود، و یک `ServerSyncService` شبیه
   `SyncService.kt`.
2. **هیچ پرس‌وجویی روی MySQL واقعی اجرا نشده.** کد سرور با PHP 8.4 لینت شده،
   مسیرها و نگهبان احراز هویت و قرارداد خطا با وب‌سرور داخلی PHP دود-تست شده‌اند،
   و تبدیل تاریخ شمسی‌اش با ۴۰۰۰ روز متوالی بررسی شده. ولی در محیط توسعه MySQL
   نبود. اولین کاری که روی هاست باید بکنید باز کردن `install-check.php` است.
3. **دو ردیف «ایلام» با کد ۴۰۱ و ۴۰۲.** هر دو عمداً نگه داشته شده‌اند چون کد
   رسمی شرکت توزیع‌اند، ولی نام متمایزی برایشان نداریم. در فهرست انتخاب، کد کنار
   نام نمایش داده می‌شود تا کارشناس بتواند تشخیص بدهد. اگر نام واقعی هر دو معلوم
   شد، در `county_names` داخل `strings.xml` اصلاح کنید.
4. **تست‌های واحد منطق خالص را پوشش می‌دهند، نه رابط کاربری.** ۹ فایل تست برای
   تاریخ شمسی، کد رهگیری، توان، شرط تکمیل، چرخه تأیید، مهلت ارسال، عملکرد واحدها
   و اعتبارسنجی. تست رابط کاربری (Compose UI test) نوشته نشده.

## ۱۰. چیزهایی که وقتتان را می‌گیرند اگر ندانید

- **APK نصب نمی‌شود / خطای امضا:** نسخه قبلی را حذف کنید. APKهای CI با کلید
  یک‌بارمصرف امضا می‌شوند و روی هم به‌روزرسانی نمی‌شوند.
- **اپ کارشناس و مدیر روی یک گوشی:** مشکلی نیست، `applicationIdSuffix` فرق
  دارد.
- **در اولین اجرا سروری تنظیم نشده و کسی نمی‌تواند وارد شود:** این حالت پیش‌بینی
  شده — `AccountRepository.localOnly()`. اگر آدرس سرور خالی باشد، ورود محلی
  انجام می‌شود تا بشود رفت و همان آدرس را در تنظیمات نوشت.
- **مختصات یا بارکد یا دوربین کار نمی‌کند:** اول مجوزها. بعد لاگ `CrashReporter`
  که خطا را داخل اپ نگه می‌دارد و در صفحه خطا نشان می‌دهد.
- **`./gradlew assembleDebug` دو فایل می‌سازد، نه یکی:** هر دو flavor را
  می‌سازد. اگر یکی را می‌خواهید، `assembleExpertDebug` یا
  `assembleManagerDebug`. خروجی‌ها در
  `android/app/build/outputs/apk/<flavor>/debug/` هستند.
- **رشته‌ای اضافه کردید و بیلد شکست:** احتمالاً نام تکراری است.
  `python3 tools/verify-resources.py` در یک ثانیه می‌گوید کدام، جای پنج دقیقه
  انتظار برای merger منابع.
