# پروتکل همگام‌سازی — راهنمای پیاده‌سازی سمت ویندوز

گوشی **سرویس‌دهنده** است و ویندوز **می‌کِشد**. اپ هیچ‌وقت نمی‌داند طرف مقابل چیست؛
فقط روی پورت ۸۷۶۵ پاسخ می‌دهد. همین باعث می‌شود وای‌فای، کابل USB و در آینده یک سرور،
همگی یک مسیر کد داشته باشند.

## ۱. برقراری اتصال

| مسیر | کاری که ویندوز می‌کند |
|---|---|
| وای‌فای | آدرس نمایش‌داده‌شده روی گوشی را باز می‌کند: `http://<ip>:8765` |
| کابل USB | `adb forward tcp:8765 tcp:8765` و بعد `http://127.0.0.1:8765` |
| آفلاین | فایل `.cvz` را از گوشی می‌گیرد و وارد می‌کند |

## ۲. احراز هویت

کاربر روی گوشی «شروع همگام‌سازی» را می‌زند و یک کد شش‌رقمی می‌بیند. ویندوز آن را
در هر درخواست می‌فرستد، به یکی از دو شکل:

```
هدر:      x-pair-code: 481920
یا پارامتر: ?code=481920
```

بدون کد، همه نقاط انتهایی جز `/ping` پاسخ `401` می‌دهند. کد با توقف سرور باطل می‌شود.

## ۳. نقاط انتهایی

### `GET /ping`
```json
{ "device_id": "…", "expert_code": "1042", "schema_version": 1, "app": "crypto-inspection" }
```
اگر `schema_version` با نسخه ویندوز یکی نبود، ادغام را انجام ندهید.

### `GET /manifest?since=<unix_millis>`
```json
{ "reports": [ { "id": "…", "updated_at": 1757000000000 } ] }
```
`since` را برابر بزرگ‌ترین `updated_at`ی بگذارید که قبلاً با موفقیت وارد کرده‌اید.

### `GET /report/<id>`
کل پرونده در یک شیء JSON. نام کلیدها دقیقاً نام ستون‌های پایگاه داده است
(`windows/SCHEMA.md`)، به‌علاوه پنج آرایه فرزند:
`devices`، `attendees`، `media`، `attachments`، `dispatches`.

هر عضو `media` و `attachments` میدان `file_path` نسبی دارد؛ فایل خام را با
`GET /media/<id>` بگیرید (`id` همان شناسه ردیف رسانه یا پیوست است).

### `GET /media/<id>`
بدنه پاسخ، خود فایل است با `Content-Type` مناسب.

### `POST /ack`
```json
{ "ids": ["…", "…"] }
```
پاسخ:
```json
{ "acknowledged": 2, "synced_at": 1757000123456 }
```
گوشی `synced_at` این پرونده‌ها را جلو می‌برد؛ دفعه بعد دیگر در صف ارسال نیستند.
**تا وقتی فایل‌های رسانه را هم نگرفته‌اید `ack` نفرستید.**

## ۴. ترتیب پیشنهادی

۱. `GET /ping` و بررسی نسخه اسکیما
۲. `GET /manifest?since=<آخرین ادغام موفق>`
۳. برای هر شناسه: `GET /report/<id>` سپس `GET /media/<id>` برای هر رسانه و پیوست
۴. درج یا به‌روزرسانی در پایگاه داده مرکزی بر اساس `id` (UUID)
۵. `POST /ack` با فهرست شناسه‌هایی که کامل ذخیره شدند

ادغام باید **idempotent** باشد: همان `id` دوباره برسد، به‌روزرسانی می‌شود نه رکورد جدید.

## ۵. بسته آفلاین `.cvz`

فایل `.cvz` یک زیپ رمزنگاری‌شده است:

```
CVZ1 | salt(16 بایت) | iv(12 بایت) | متن‌رمز AES-256-GCM
```

کلید با `PBKDF2WithHmacSHA256` و ۱۲۰٬۰۰۰ تکرار از رمز بسته ساخته می‌شود
(رمز در تنظیمات گوشی نمایش داده می‌شود). پس از رمزگشایی، یک زیپ معمولی می‌ماند:

```
data.json              ← همان ساختار /report برای همه پرونده‌های ارسال‌نشده
media/<report_id>/…    ← فایل‌های رسانه با همان مسیر نسبی
attachments/<report_id>/…
```

`data.json` علاوه بر آرایه `reports`، میدان‌های `device_id`، `expert_code`،
`schema_version` و `exported_at` را هم دارد.
